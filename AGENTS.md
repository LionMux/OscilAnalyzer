## Обзор проекта

**OscilAnalyzer** — десктопное WPF-приложение для анализа осциллограмм в формате **COMTRADE** (файлы `.cfg` + `.dat`). Предназначено для исследования аварийных процессов в электроэнергетических системах: визуализации токов и напряжений, построения векторных диаграмм, расчёта симметричных составляющих и автоматического определения типа короткого замыкания (КЗ).

- **Язык разработки**: C# 12 (.NET 8.0-windows)
- **Тип приложения**: WPF, `OutputType = WinExe`
- **Паттерн архитектуры**: MVVM (Prism)
- **Язык комментариев и UI**: русский
- **Основное решение**: `OscilAnalyzer.sln` (Visual Studio 2022+)

### Принцип навигации

Приложение использует **регионы Prism**:
- `ContentRegion` в `MainWindow` — единственный регион.
- При старте открывается `CometradeParserView`.
- По команде «Далее» происходит навигация на `AnalizeOscillogramView`.
- По команде «Назад» — возврат.

### Обмен данными между экранами

Данные не передаются через параметры навигации. Вместо этого используется зарегистрированный как **Singleton** `SignalDataService`, содержащий:
- `CurrentA/B/C`, `VoltageA/B/C` — сырые отсчёты
- `TimeValues` — временная ось (мс)
- `NumOfPoints`, `PoOfPer` — общее число точек и точек на период

## Архитектура математических вычислений

### 1. Чтение COMTRADE
- `CometradeParserViewModel` открывает диалог выбора `.cfg`.
- Создаётся `Reader` из проекта `ComtradeParser`, который парсит `.cfg` и `.dat`.
- Пользователь вручную сопоставляет каналы осциллограммы с фазами A/B/C для тока и напряжения через ComboBox.

### 2. Анализ Фурье / Герцеля
- По нажатию «Анализ Фурье» в `AnalizeOscillogramViewModel` запускается `GoertzelAnalyzer` в фоновом потоке (`Task.Run`).
- Результат: массивы комплексных фазоров `ProcessedSignalA/B/C` для токов и напряжений.
- Также вычисляются:
  - `RmsCalculator` — действующие значения по скользящему окну (1 период)
  - `SymmetricalComponentsCalculator` — симметричные составляющие (прямая `Pramaya`, обратная `Obratnaya`, нулевая `Nulevaya`)
- Прогресс отображается через `Action<double>`, привязанный к `ProgressBar`.

### 3. Векторные диаграммы
- `VectorPlotter` использует полярные оси ScottPlot.
- Ползунок / TextBox `TimeForVD` позволяет выбирать момент времени; при изменении вызывается `UpdatePlot(index)`.
- Автоматически пересчитываются и отображаются RMS значения для выбранного момента.

### 4. Определение типа КЗ
- `TypeOfFaultAnalizer` анализирует массивы симметричных составляющих и полного сопротивления по кадрам.
- Реализованы критерии для следующих типов КЗ:
  - `K3` — трёхфазное
  - `Ka1`, `Kb1`, `Kc1` — однофазные на землю
  - `Kab2`, `Kbc2`, `Kca2` — двухфазные
  - `Kab11`, `Kbc11`, `Kca11` — двухфазные на землю
- Условие регистрации КЗ: критерий должен выполняться непрерывно на `_condForRegFault` отсчётов (по умолчанию равно числу точек на период).
- Индикаторы КЗ — круглые кнопки, подсвечивающиеся жёлтым (`Brushes.Yellow`) при срабатывании.

## Стиль кода и соглашения

### Общие правила
- **Язык**: все комментарии, сообщения `MessageBox`, строки UI — на **русском** языке.
- **Namespace**:
  - Классы приложения (ViewModels, Views, Plotter и т.д.) — `OscilAnalyzer`.
  - Математические классы — `COMTRADE_parser` (исторически унаследовано от парсера).
- **Nullable reference types** включены (`<Nullable>enable</Nullable>`).
- **Implicit usings** включены.

### Именование
- ViewModel-ы наследуются от `Prism.Mvvm.BindableBase`.
- Команды — `DelegateCommand` из Prism, именуются с суффиксом `Command` (например, `StartAnalizeFourie`).
- Приватные поля с префиксом `_`.
- Некоторые термины в коде используют транслитерацию:
  - `Pramaya` — прямая (последовательность)
  - `Obratnaya` — обратная
  - `Nulevaya` — нулевая
  - `Analize` — analyze (в именах классов)

### Особенности
- Глобальный обработчик необработанных исключений в `App.xaml.cs` пишет в файл `errors.txt` и показывает `MessageBox` с текущей директорией.
- В `AnalizeOscillogramViewModel` вычисления выполняются в `Task.Run`, а UI-обновления — через `BindableBase`/`SetProperty` (Prism автоматически маршализует `PropertyChanged` в UI-поток, если используется стандартный `DelegateCommand`).

## Тестирование

- **В проекте OscilAnalyzer отсутствуют unit-тесты.**
- В родительской директории `OscillAnalizer/Gemstone.Comtrade/src/UnitTests/` есть тесты для библиотеки Gemstone.COMTRADE, но они не относятся к логике данного приложения.
- Ручное тестирование выполняется с помощью образцовых файлов в папке `Files/`.

### Проверка функциональности вручную
1. Запустить приложение.
2. Нажать «Считать осциллограмму» и выбрать `Files/25_newRTDS.cfg`.
3. Выбрать каналы токов и напряжений из выпадающих списков.
4. Нажать «Применить выбранные сигналы» — должны отобразиться 6 графиков.
5. Нажать «Далее».
6. Нажать «Анализ Фурье» — должны появиться векторные диаграммы и RMS.
7. Переместить ползунок времени — диаграммы должны обновиться.
8. Нажать «Вид КЗ» — индикаторы должны изменить цвет при выявлении замыкания.

## Безопасность и надёжность

- **Нет шифрования и авторизации** — это локальное инженерное приложение.
- **Файловые операции**: диалог `OpenFileDialog` ограничен фильтром `*.cfg`. Соответствующий `.dat` файл ищется по замене расширения.
- **Глобальный try-catch** в `CometradeParserViewModel.ReadSignal()` перехватывает ошибки парсинга и показывает `MessageBox`.
- **UnhandledException** в `App.xaml.cs` записывает crash-лог в `errors.txt` в текущей директории (обычно рядом с `.exe`).
- При делении на ноль в расчёте импеданса (`TypeOfFaultAnalizer.CalculateImpedance`) установлено запасное значение `10 ^ 8` (в коде фактически `10 ^ 8` — это побитовое XOR, но логика рассчитана на большое число).

## Внешние зависимости и проекты-спутники

Репозиторий `OscillAnalizer/` содержит несколько проектов:
- `OscilAnalyzer/` — текущий проект (WPF-приложение).
- `ComtradeParser/` — самописная библиотека парсинга COMTRADE (упрощённый парсер ASCII).
- `Gemstone.Comtrade/` — форк/клон библиотеки Gemstone с собственными unit-тестами.
- `ComtradeCutForCNN/` и `CoomtradeCutForCNN/` — вспомогательные утилиты (не связаны напрямую со сборкой основного приложения).

При изменении API `ComtradeParser` необходимо убедиться, что контракты `Reader`, `ComtradeConfig`, `AnalogChannelConfig` остаются совместимыми.

## Часто используемые точки расширения

- **Добавление нового типа КЗ**: расширить `TypeOfFaultAnalizer` новым флагом, счётчиком и методом-критерием; добавить соответствующую кнопку и Brush-свойство в `AnalizeOscillogramViewModel`; привязать во View.
- **Замена алгоритма спектрального анализа**: реализовать `ISignalAnalizer`, заменить создание `GoertzelAnalyzer` в `AnalizeOscillogramViewModel`.
- **Новый экспорт**: методы в `CsvExporter` статические, можно добавить перегрузки с другими форматами.
- **Новый экран**: зарегистрировать View + ViewModel в `App.RegisterTypes`, выполнять навигацию через `IRegionManager`.
